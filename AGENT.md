# AGENT.md

## Repository rules

- Treat `scripts/patch-extension-*.mjs` as the maintained source for BMG changes to the upstream Edge extension. `extension/` is a generated, ignored runtime artifact and must not be committed.
- Rebuild the extension through `scripts/setup.ps1`; it verifies the pinned upstream archive SHA256 before applying BMG patches.
- Keep navigation behavior in `scripts/patch-extension-navigation.mjs`, content fallbacks in `scripts/patch-extension-web-content.mjs` / `scripts/patch-extension-content-cdp.mjs`, and do not duplicate responsibilities across patchers.
- Keep upstream public-tool targeting and record/replay workspace isolation in `scripts/patch-extension-upstream-tools.mjs`. BMG should expose the complete public tool catalog of the pinned `chrome-mcp-shared` version plus dynamic `flow.<slug>` tools; do not maintain duplicate upstream tool schemas in the sidecar.
- Append BMG-specific model guidance only to the relevant upstream tool description in `augmentWorkspaceTools`; preserve upstream names, input schemas, and descriptions for unrelated tools.
- Upstream tools that use active/currentWindow semantics must be converted to explicit BMG tab/window targeting before they are reachable through the public BMG endpoint. Dynamic flow tab/window creation, switching, lookup, and closing must stay inside the ownership-verified BMG workspace window.
- Browser automation from local external consumers must go through `bmgctl`; do not read the approval secret or call private `/internal/*` endpoints directly.
- Treat any change to MCP `tools/list`, public tool names, tool descriptions, or input schemas as a ChatGPT plugin/app rebuild event. Restarting the BMG sidecar alone is not sufficient because ChatGPT may retain the previously built tool schema.
- When a rebuild is required, give the user a local PowerShell block that prints the two values needed for the ChatGPT plugin/app rebuild: the public MCP URL from `BMG_RESOURCE` and the OAuth approval key stored at `BMG_APPROVAL_SECRET_FILE`. Prefer the README's absolute-path, direct-current-session form: do not wrap a block containing `$variables` inside an outer double-quoted `powershell.exe -Command "..."`, because the caller shell can expand those variables before the inner PowerShell receives them. This BMG OAuth flow uses dynamic client registration + PKCE with no static client secret; in this workflow, "OAuth key" means the approval secret entered on the BMG consent page.
- Never execute that secret-printing command on the user's behalf, capture its output, read the approval-secret file, or paste the secret into chat. The user must run it locally and use the values themselves during rebuild/reconnection.
- Preserve BMG workspace ownership checks. Never hide, show, move, close, or repurpose an Edge window unless its HWND/marker/process ownership has been verified.
- Workspace recovery must not be suppressed merely because unrelated Edge processes already exist. Recovery may launch a new nonce-marked bootstrap window, but it must not alter unverified Edge windows.
- While a bootstrap claim is still inside the 30-second startup grace window, recovery must reuse that pending claim instead of overwriting its state or launching another bootstrap window.
- After the startup grace expires, a pending bootstrap must be explicitly claimed, confirmed absent, or ownership-verified and retired before its state is replaced. Never create another bootstrap merely because the previous state is old, and never retire an entire Edge process to clean up a bootstrap HWND.
- Page automation is background-first. Keep window visibility and foreground activation distinct: `bmg_show_workspace` without arguments makes the owned BMG window visible without taking focus; pass `activate: true` only when the user explicitly asks to focus, activate, switch to, or bring BMG to the foreground. Merely asking to show/display the window is not a foreground request. Explicit `background: false` on supported page tools and the element picker are foreground actions.
- Non-activating workspace display must use Win32 `SW_SHOWNA (8)` and keep the existing maximized/normal state and geometry. The hide helper's minimized-window preparation is a distinct path; do not change it without validating minimized-to-hidden behavior.
- Record every owned workspace show/hide transition (including implicit maintenance), command acceptance, helper failure, Win32 visibility/style outcome, and taskbar API completion in the append-only `logs/bmg-window-transitions.jsonl`. Never log URL, page title, OAuth material, or ownership marker. A successful `AddTab`/`DeleteTab` COM return is not proof of the actual Explorer taskbar UI; keep that distinction explicit. Logging failures must not affect window operations.
- If a tool call temporarily shows the BMG workspace and then fails before a normal result is observed, best-effort true-hide that ownership-verified workspace on the failure path; maintenance failure must not replace the original tool/upstream error.
- Idle cleanup may only affect tabs in the ownership-verified BMG workspace window; ordinary Edge windows are out of scope.
- Idle cleanup must not proactively recover or launch Edge when the browser/upstream is offline. Browser recovery remains demand-driven so intentionally closing Edge does not cause a later idle timer to reopen it.
- Use `node.exe --test tests\sidecar.test.mjs` for the trusted full Node test run under CCM. Also run `git diff --check` before committing.
- Keep `README.md` synchronized with the current implementation and real validation status. Remove obsolete names and descriptions instead of retaining defensive legacy wording.
- Keep `assets/bmg-mcp-icon.png` as the manually uploaded BMG ChatGPT MCP plugin icon. Validate that it is a readable square PNG under 10,000 bytes; do not replace manual upload with an image URL or confuse it with another project's icon.
- When the repository has a remote, finish completed implementation work by committing and pushing the intended branch.

## BMG MCP approval and phone authorization

- Keep the accepted WCM semantics in the BMG Sidecar approval layer: timed, totp and off modes; independently frozen owner actions; a card-specific nonce; exact-ID timed grants; single-use owner execution; and policy-revision revocation. BMG's grant covers all public BMG browser tools, not WCM devices.
- Every OAuth-protected public tools/call, including BMG workspace controls and dynamic flow tools, must pass the Sidecar approval gate before reaching the extension or local workspace handler. Strip approval_id before upstream dispatch. Reject JSON-RPC batch requests. The loopback-only, local-secret-protected bmgctl management path is separate.
- Keep app-only get_approval_status and resolve_pending_action, nonce and optional Host-session binding, card remount revalidation, display-only historical receipts, and non-replayable owner actions. Widget state is never authoritative. Failed ChatGPT continuation must not replay an approved action.
- In totp mode require a fresh user-provided phone code via bmg_unlock or an exact active grant ID; missing authorization fails closed without creating a card. Do not activate phone mode before local pairing. The DPAPI CurrentUser seed lives in %LOCALAPPDATA%\BMG\secrets and belongs to the local BMG Controller account. Never use CCM/BMG to run manage-bmg-totp.ps1 with Init or ReadForRouter, or to display the production seed; only the user enrolls/validates the phone in a private local terminal.
- Before changing PowerShell TOTP confirmation logic, run scripts/manage-bmg-totp.ps1 -Action SelfTest through CCM. Test with synthetic secrets, never a production code. Policy mode/revision changes revoke all active grants and pending approvals.
- Approval-related public tool schemas or MCP resources require a ChatGPT BMG plugin/app rebuild. Keep README.md synchronized; give the user the local OAuth URL/key print block to run privately and do not read that key yourself.
